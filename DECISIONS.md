## 2026-09-23 — Real, database-backed rooms (mockRooms.ts retired)

- **`apps/web/lib/mockRooms.ts` is gone.** Rooms, joining, and participants now go through `@huddle/db` (Drizzle, `DATABASE_URL`) via new route handlers, so a room created on one device is a real row a friend's device can find and join — this is the thing the local-only mock explicitly could not do.
- **Hosting a room uses Supabase anonymous auth, not full sign-up.** `rooms.host_id` is `NOT NULL references users.id` by schema design (see Phase 0–1 entry) — no guest-host path exists in the data model, unlike participants/messages/picks which all support a `guestId` alternative. Rather than changing that schema, `apps/web/lib/supabaseClient.ts` calls `supabase.auth.signInAnonymously()` client-side (no email/password, just whatever name they typed) before creating a room; `POST /api/rooms` then upserts a lightweight `users` row keyed by that Supabase auth id. This matches what `users.authId` was already clearly meant for (comment in schema.ts: "mirrors the Supabase Auth user id"). **Requires Anonymous Sign-Ins to be turned on in Supabase** (Authentication → Sign In / Providers → Anonymous) — off by default. Not yet confirmed on; "Start a room" will fail with a visible error until Mo flips it.
- **Joining a room stays frictionless — no auth at all.** `POST /api/rooms/[code]` inserts a `guest_sessions` row (24h `expiresAt`) plus a `room_participants` row with `guestId` set, mirroring the existing guest pattern already used for messages/picks. A guest never touches Supabase Auth.

A room started from Home's "Tonight" card instead carries the real ESPN game id/teams/time through as query params from `/` → `/create` → `POST /api/rooms`, which upserts a real `events` row keyed by that ESPN id (`events.provider_event_id` has a unique index, so the same game reused across rooms doesn't duplicate).

Video/audio/chat still aren't wired up (LiveKit), and the room screen still says so explicitly. Swapping polling for Supabase Realtime channels is a natural next step once that's worth the complexity.
- **"Leave" marks `room_participants.left_at`** via `POST /api/rooms/[code]/leave`, keeping the existing `room_participants_active_room_idx` (`WHERE left_at IS NULL`) meaningful — active-participant queries actually reflect who's still there.

Any time `apps/web/package.json` dependencies change, `pnpm-lock.yaml` must be regenerated and committed too.

Any Postgres password with special characters (`#$@:/?%` and space, at minimum) needs percent-encoding when placed in a `postgresql://` URL, or it fails in confusing, non-obvious ways. Fixed by rebuilding the full Transaction pooler string from Supabase's Connect panel with the password properly encoded, replacing the entire Netlify env var value (not just the password portion).
